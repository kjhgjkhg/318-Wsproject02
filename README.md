**你现在是一个Python全栈开发专家。请根据以下需求编写一个模块化的、可维护的Python本地Markdown笔记快速搜索与标签统计工具（CLI版）。**

**任务描述**  
开发一个命令行工具，用于扫描本地 Markdown 笔记文件夹（.md 文件），支持关键词全文搜索、按标签/前缀过滤、统计热门标签/关键词，并生成搜索结果或统计报告。程序只读取源文件，不做任何修改，输出结果保存为纯文本报告。

**功能需求**  
1. 支持的子命令（使用 argparse 实现）：  
   - notes search "关键词"       → 搜索包含关键词的笔记，显示文件名 + 匹配行预览  
   - notes tags                   → 列出所有出现的标签（#tag 形式），按出现次数降序  
   - notes stats                  → 统计：笔记总数、总行数、热门前10标签、常见前缀（如 [[链接]] 的双链数量）  
   - notes list --tag work        → 列出带有指定标签的笔记文件名  
   - notes report                 → 生成完整统计报告并保存到输出目录  
2. 标签识别规则：标准 Markdown #tag（支持 #tag/subtag，多级标签算独立）  
3. 搜索支持：大小写不敏感、支持多个关键词（AND 逻辑）  
4. 报告格式：纯文本，包含表格、分隔线、排序列表  
5. 只处理 .md 文件，忽略其他格式

**强约束（必须写进提示最显眼位置，AI必须严格100%遵守）**

**路径与文件约束**  
- 只能使用两个固定目录：  
  笔记扫描目录（只读）： ./source_data/ （用户 Markdown 笔记存放处，程序**严禁**在此目录创建、修改、删除、重命名任何文件）  
  输出目录（只写）： ./output_build/ （用于保存搜索结果报告、统计报告，如 search_report.txt / stats_report.txt）  
- 目录中存在一个名为 .do_not_touch.cfg 的文件，程序可以读取但**严禁修改、重命名或删除**它或源目录内任何文件

**文件命名与结构约束**  
- 所有模块文件名**必须**小写+下划线，且**强制**使用以下前缀开头：core_、search_、stats_、cli_、util_  
- **必须**拆分成**至少6个独立文件**，结构严格如下（文件名与层级不可更改）：

  ├── main.py                   # 唯一入口，argparse 子命令解析与流程调度
  ├── core_note.py              # Note 数据结构（文件名、内容、提取的标签/链接等）
  ├── search_engine.py          # 全文搜索、关键词匹配、行预览逻辑
  ├── stats_analyzer.py         # 标签统计、关键词频率、前缀计数、报告生成核心
  ├── cli_commands.py           # 子命令具体实现（search / tags / stats / list / report）
  ├── utils/validators.py       # 输入校验（关键词合法、路径存在、标签格式等）
  └── utils/config.py           # 常量（源目录、输出目录、常见标签前缀、报告文件名模板等）

**技术约束**  
- Python 版本：仅限 3.9 \~ 3.11  
- **严禁**使用任何第三方库（无 whoosh、lunr、markdown、frontmatter、rich、tabulate 等）
